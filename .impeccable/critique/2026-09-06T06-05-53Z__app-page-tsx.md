## Priority Issues

**[P0] Social-preview crawlers may get markdown, not HTML -- OG tags invisible to them.**
Why it matters: `curl` with a generic `Accept: */*` (curl default -- also what many simple link-unfurl bots send) got back `Content-Type: text/markdown`, not the real HTML page with `og:*`/`twitter:*` tags. If any platform's preview crawler doesn't send a full browser-shaped `Accept: text/html,...` header, it never sees the OG meta at all.
Fix: `middleware.ts` should require an explicit, unambiguous markdown preference (only serve markdown when `text/markdown` has strictly higher quality than `text/html` AND `*/*` is not the only signal), or exempt known crawler/bot user-agents from the markdown branch entirely.
Suggested command: `/impeccable harden`

**[P0] og:image declared dimensions are factually wrong.**
`app/layout.tsx` declares `width:1792, height:2388` (portrait); actual file (`sips`, confirmed independently by both agents) is `2752x1536` (landscape 16:9, matches filename). Platforms trusting declared metadata pre-fetch can reserve/crop the wrong box for link-preview cards.
Fix: correct the numbers to 2752x1536; consider a purpose-built 1200x630 share card (name + credential legible at thumbnail size) rather than reusing a hero photo.
Suggested command: `/impeccable polish`

**[P1] Hero H1 renders at ~59% opacity at first paint.**
Confirmed via `getComputedStyle`: white H1 text at `opacity:0.586895` on load, self-corrects to 1 after any scroll. Root cause: `Hero.tsx:9-15`, `useTransform(scrollYProgress,[0,0.6],[1,0])` -- `scrollYProgress` isn't reliably 0 at mount. Reproduces on desktop and mobile viewport.
Fix: clamp/initialize opacity to 1 before the scroll listener attaches, or gate the transform on a mounted/ready flag.
Suggested command: `/impeccable polish`

**[P1] Stock photography contradicts a documented hard rule.**
`Journey.tsx`/`MedicalSpecialties.tsx` use filenames like `...group-surgeons-wearing-safety-masks...jpg`, alt "Surgeons performing operation" -- generic strangers, not the doctor. PRODUCT.md anti-reference explicitly says "avoid stock-photo clutter."
Fix: replace with existing real photos in `public/` (12+ available) or drop the imagery for text/iconography.
Suggested command: `/impeccable polish`

**[P1] AI/agent-facing content surface (llms.txt / index.md / markdown.ts) is stale.**
Both agents independently confirmed: generic 3-bullet specialty summary, no mention of the three named clinics (Araya/NURA/Izee), no fellowship (2025-2026), no journey/experience detail -- while the live HTML page has all of it. CLAUDE.md itself flags these as hand-maintained duplicates requiring sync; recent commits (Araya Clinic, Messenger link, fellowship fix) never touched them.
Fix: expand to match current page content; add a checklist reminder whenever Contact/Experience/Journey copy changes.
Suggested command: `/impeccable document`
